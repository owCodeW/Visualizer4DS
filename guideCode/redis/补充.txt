# 一、升级后项目核心定位（最重要的变化）
不仅展示**数据结构长什么样**，更展示：
## **你做什么操作 → 底层自动切换什么编码/结构**

例如：
- String 从 `int` → 修改成字符串 → 变成 `embstr`
- String 超过 44 字节 → 变成 `raw`
- List 元素少 → `listpack`，元素多 → `quicklist`
- Hash / ZSet 元素少 → `listpack`，元素多 → `hashtable/skiplist`

**全部实时可视化、自动切换、带提示、带原因说明。**

# 二、新增核心学习模块：编码自动转换机制
## 1. 支持展示的「编码类型与切换规则」
### （1）String 编码（最重要）
- int（整数）
- embstr（短字符串优化）
- raw（长字符串）

**会展示：**
- 当前编码是什么
- 编码切换的触发条件
- 执行修改操作后编码如何变化

### （2）List 编码
- listpack（紧凑结构）
- quicklist（链表+listpack）

### （3）Hash 编码
- listpack（元素少时）
- hashtable（元素多时）

### （4）Set 编码
- intset（整数集合）
- hashtable（非整数/元素多时）

### （5）ZSet 编码
- listpack（元素少时）
- skiplist+hashtable（元素多时）

# 三、操作如何影响底层编码（核心教学点）
平台会**实时显示**：
1. 你执行了什么命令
2. 为什么触发编码切换
3. 切换前是什么
4. 切换后变成什么
5. 对应的 Redis 源码规则

## 例如 String 演示流程：
1. 添加 `100` → 编码：**int**
2. 修改成 `hello` → 编码：**embstr**
3. 修改成超长字符串 → 编码：**raw**
4. 页面自动提示：**编码已切换 + 切换原因 + 阈值说明**

## 例如 Hash 演示流程：
1. 添加少量字段 → 结构：**listpack**
2. 持续添加字段 → 结构：**hashtable**
3. 页面提示：**达到阈值，自动升级结构**

# 六、前端交互升级（最直观）
## 1. 编码切换提示
当你操作导致结构变化时：
- 弹出提示：`编码已从 int → embstr`
- 显示原因：`因为从整数修改为非整数`

## 2. 结构视图自动刷新
- int 用蓝色框
- embstr 用绿色框
- raw 用红色框
不同编码用**不同颜色**区分，一眼看懂。

## 3. 操作日志显示完整链路
```
执行：SET key hello
原编码：int
新编码：embstr
原因：整数被修改为字符串
```

# 七、项目整体流程（最终版）
1. 打开网页 → 选择数据类型（String/List/Hash 等）
2. 前端获取：初始结构 + 当前编码 + 阈值
3. 你执行操作（增/删/改）
4. 后端判断：
   - 是否改变数据格式
   - 是否达到编码切换阈值
   - 是否需要自动转换结构
5. 后端返回：
   - 新结构
   - 新编码
   - 切换原因
6. 前端：
   - 刷新视图
   - 播放动画
   - 显示提示
   - 记录日志
