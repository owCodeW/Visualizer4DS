# MVCC隔离级别与Read View机制详解

# 前置基础说明

## 核心前置规则

1. 初始数据：`id=1, age=20`；新增测试数据辅助幻读：无其他行，后续 A 新增`id=2`用于演示幻读

2. 事务 A：写事务，写操作分配`trx_id=100`；事务 B：纯只读事务，无全局事务 ID，懒分配 Read View（BEGIN 不生成快照，第一次 SELECT 才创建快照，即懒加载不分 ID）

3. MVCC 核心概念

    - Undo Log：数据修改前镜像，用于快照读回溯旧数据

    - Read View（快照视图）：存储当前活跃未提交事务集合，判断数据版本可见性

    - RC：**每次 SELECT 都新建 Read View**；RR：**事务内第一次 SELECT 创建 Read View，全程复用不更新**

4. 现象定义

    - 脏读：读到其他事务未提交的修改

    - 不可重复读：同一事务内，两次相同 SELECT，中间其他事务提交更新，两次结果不一致（RC 原生出现，RR 规避）

    - 幻读：同一事务内，两次范围 SELECT，中间其他事务插入 / 删除提交，两次结果行数不一致（RR 快照读规避幻读，当前读仍存在）

5. 时序扩充：在原有 T1\-T5 基础上新增 T6\-T8，补充脏读验证、幻读场景、当前读对比

# 表格一：读已提交 RC 隔离级别 完整时序演进（含脏读 / 不可重复读演示）

RC 核心特性：每次快照读 SELECT 都会**重新生成 Read View**，BEGIN 仅开启事务，不创建快照（懒加载不分 ID）；允许不可重复读，无脏读（不会读取未提交事务修改）

|时间线|事务 A \(写 trx\_id=100\)|事务 B \(只读 MVCC 快照读视界\)|

|T0 初始化|数据库基线数据：`id=1,age=20`，无活跃事务，Undo 日志为空|未启动|
|T1 双方 BEGIN|执行 `BEGIN;`，仅开启事务，无写操作，未分配 trx\_id，不生成 Undo，无快照|执行 `BEGIN;`；RC 懒加载规则：BEGIN 不创建 Read View，无快照、不分配视图（不分事务 ID）|
|T2 A 更新未提交|执行 `UPDATE t SET age=21 WHERE id=1;` <br>1\. 分配写 trx\_id=100，写入当前行隐藏列 trx\_id=100 <br>2\. 生成 Undo Log 存储旧镜像`age=20` <br>3\. trx\_id=100 加入**活跃事务列表** <br>4\. 未 COMMIT，数据仅内存变更，未持久化|无操作，无快照|
|T3 B 第一次 SELECT（首次生成快照）|保持未提交，trx\_id=100 仍活跃|执行 `SELECT age FROM t WHERE id=1;` <br>1\. RC 懒加载触发：首次 SELECT 新建 Read View <br>2\. Read View 记录当前活跃列表：\[100\] <br>3\. 读取行 trx\_id=100 属于活跃未提交事务，走 Undo Log 回溯旧镜像 <br>4\. 查询结果：20；无脏读|
|T4 A 提交事务|执行 `COMMIT;` <br>1\. trx\_id=100 从活跃事务列表移除 <br>2\. 修改持久化，Undo 日志暂保留（供其他事务回溯）|无操作，原有 Read View 销毁（RC 不保留快照）|
|T5 B 第二次 SELECT（重建快照，触发不可重复读）|已提交，数据永久为`age=21`，无活跃写事务|执行 `SELECT age FROM t WHERE id=1;` <br>1\. RC 规则：每次 SELECT**重建全新 Read View** <br>2\. 新视图活跃列表为空，无未提交事务 <br>3\. 直接读取当前最新已提交数据，无需 Undo 回溯 <br>4\. 查询结果：21 <br>现象：同一事务两次查询结果不同 → **不可重复读（RC 固有问题）**|
|T6 A 新增插入（幻读前置操作）|执行 `INSERT INTO t(id,age) VALUES(2,22); COMMIT;` <br>插入新行并立即提交，数据库现有两行：id1、id2|无操作|
|T7 B 第三次范围 SELECT（再次新建快照，触发幻读）|无操作|执行 `SELECT * FROM t WHERE age>10;` <br>1\. 再次重建 Read View，读取全局最新已提交数据 <br>2\. 查询到 2 行数据 \(id1、id2\) <br>现象：若 B 在 T3 执行过相同范围查询仅 1 行，本次 2 行 → **RC 存在幻读**|

## RC 总结

1. 无脏读：通过 Read View 过滤活跃未提交事务，依靠 Undo 回溯旧数据

2. 存在不可重复读：每次 SELECT 重建快照，能读到中途提交的更新

3. 存在幻读：范围查询每次刷新快照，可感知其他事务已提交的插入 / 删除

# 表格二：可重复读 RR 隔离级别 完整时序演进（规避不可重复读、快照读规避幻读）

RR 核心特性：**懒加载快照，仅事务内第一次 SELECT 创建 Read View，整个事务全程复用同一快照，永不重建**；规避不可重复读；快照读无幻读，当前读（update/delete/select \.\.\. for update）仍存在幻读

|时间线|事务 A \(写 trx\_id=100\)|事务 B \(只读 MVCC 快照读视界\)|
|---|---|---|
|T0 初始化|基线数据：`id=1,age=20`，无活跃事务，Undo 日志为空|未启动|
|T1 双方 BEGIN|`BEGIN;`，无写操作，无 trx\_id、无 Undo、无快照|`BEGIN;`；RR 懒加载规则：BEGIN 不生成 Read View，不分配快照（不分事务 ID，快照延迟至第一次查询）|
|T2 A 更新未提交|`UPDATE t SET age=21 WHERE id=1;` <br>1\. 分配 trx\_id=100，行隐藏事务 ID 更新为 100 <br>2\. Undo Log 保存旧镜像 age=20 <br>3\. trx\_id=100 加入活跃事务列表 <br>4\. 未提交，变更仅内存生效|无操作，无快照|
|T3 B 第一次 SELECT（唯一一次创建快照）|trx\_id=100 保持活跃未提交|`SELECT age FROM t WHERE id=1;` <br>1\. RR 懒加载触发：**全事务仅此处生成一份 Read View**，永久复用 <br>2\. Read View 快照记录：活跃列表 \[100\]、当前最大事务 ID <br>3\. 行 trx\_id=100 属于快照内活跃事务，走 Undo Log 回溯旧版本 <br>4\. 查询结果：20|
|T4 A 提交事务|`COMMIT;` <br>1\. trx\_id=100 移出活跃事务列表 <br>2\. 数据持久化为 age=21，Undo 日志保留|B 持有的 T3 旧 Read View**完全保留，不刷新、不重建**|
|T5 B 第二次 SELECT（复用旧快照，消除不可重复读）|已提交，最新数据 age=21|`SELECT age FROM t WHERE id=1;` <br>1\. RR 规则：复用 T3 创建的原始 Read View，不重新拍照 <br>2\. 快照内仍记录 trx\_id=100 为当时活跃事务，无视其已提交事实 <br>3\. 强制走 Undo Log 回溯事务启动前的旧镜像 <br>4\. 查询结果：20 <br>现象：两次查询结果一致 → **规避不可重复读**|
|T6 A 插入新行并提交（幻读测试）|`INSERT INTO t(id,age) VALUES(2,22); COMMIT;` <br>数据库新增 id=2，已持久化提交|B 的 Read View 依旧是 T3 旧快照，快照视图中不存在 id=2 这条新版本数据|
|T7 B 第三次范围快照 SELECT（快照读无幻读）|无操作|`SELECT * FROM t WHERE age>10;` <br>1\. 复用 T3 旧 Read View，快照只包含事务启动时基线数据 <br>2\. 无法感知 T6 新增的已提交 id=2 行 <br>3\. 仅查询到 1 行 \(id=1\) <br>现象：前后范围查询行数不变 → **RR 快照读规避幻读**|
|T8 B 执行当前读（锁读，幻读重现）|无操作|`SELECT * FROM t WHERE age>10 FOR UPDATE;` <br>1\. 当前读放弃 MVCC 快照，直接读取数据库最新已提交数据 <br>2\. 读取到 id1、id2 共 2 行 <br>补充：RR 仅快照读无幻读，加锁当前读仍存在幻读|
|T9 脏读验证时序补充|T\-1：A 更新 age=21 未提交，未执行 COMMIT|T\-2：B 执行 SELECT；快照识别 A 为活跃事务，回溯 Undo 读到 20，**RR 同样不会产生脏读**|

## RR 总结

1. 无脏读：同 RC 逻辑，快照过滤未提交活跃事务，依靠 Undo 回溯旧数据

2. 规避不可重复读：全程复用首次 SELECT 生成的 Read View，不刷新视图

3. 快照读无幻读：快照锁定事务第一次查询时的全局数据视图，隔离后续其他事务的插入 / 删除；加锁当前读仍存在幻读
